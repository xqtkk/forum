# Обзор после версии 2

Go + HTML-шаблоны + SQLite остаются подходящей основой для этого форума. Переписывать проект на другой стек не требуется.

## Фундаментальные доработки из предыдущего обзора

1. **Транзакции:** реакции, счётчики, история и уведомления изменяются вместе. Создание поста/комментария, одобрение роли и восстановление аккаунта откатываются целиком при ошибке. Есть тесты принудительного сбоя и конкурентных запросов.
2. **Целостность:** версионируемые миграции, копия перед изменением, включённые FK, каскадное удаление и NULL для исторических ссылок. Осиротевшие строки архивируются; счётчики восстановлены из реакций.
3. **TLS:** общий закрытый ключ исключён из нового приложения. Локальный сертификат индивидуален; публичный запуск требует собственного TLS или явно доверенного прокси.
4. **Обслуживание:** пагинация, ограничения текстов и файлов, подтверждение почты, восстановление пароля, OAuth-привязка, лимиты входа, очистка истёкших записей, graceful shutdown, журналы без токенов и ежедневные копии.
5. **Структура приложения:** общий пул передаётся в запрос через App, обработчики не закрывают его. Многошаговые операции находятся в database. Рендер буферизован, layout общий. Часть простых SELECT пока остаётся в старых обработчиках; дальнейшее выделение сервисов возможно постепенно.
6. **Очистка:** удалён неиспользуемый `static/sql.go` со старым глобальным подключением и разрушительным пересозданием таблицы `posts`; рабочая схема БД обслуживается только через миграции `database`.

## Пользовательские сценарии

Реакции не перезагружают страницу; уведомления используют правильный layout; выбранное изображение видно до отправки. Редактор комментария открывается по кнопке и подтверждается отдельно. Профили содержат био, посты и комментарии; почта доступна только владельцу. Запрошенный модератор создан с индивидуальным паролем без пароля в исходниках.

## Практические границы

OAuth и доставка писем требуют credentials владельца. SMTP и контейнеры не проверены в боевом окружении. Копии БД на том же диске необходимо дополнить внешним хранением и копиями uploads. Ограничение IP может объединять людей за NAT, поэтому добавлен отдельный лимит по аккаунту. Срок сессии настраивается через `SESSION_TTL` (по умолчанию 24 часа), и действует одна активная сессия на пользователя.

Перед публичным запуском нужны домен, почта, TLS, хранение данных и проверка конфигурации. Инструкции — в UPDATE_V7_RU.md. Эти изменения и тесты не являются обещанием отсутствия всех уязвимостей.
